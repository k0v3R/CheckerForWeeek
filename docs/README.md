# Checker for Weeek (расширение для Chromium-браузеров)

Расширение показывает количество непрочитанных уведомлений из [app.weeek.net](https://app.weeek.net) на иконке, открывает список непрочитанных по клику, умеет помечать и архивировать их через меню «⋯» на плитке, проигрывает собственный звук и показывает системный тост Windows при новых уведомлениях. Интервал проверки, звук, тосты Windows и путь до задачи настраиваются в самом попапе — кнопка настроек в шапке.

**Показ попапа ничего не помечает прочитанным** — при показе выполняются только GET-запросы. Клик по плитке или тосту — осознанное действие пользователя: уведомление помечается прочитанным (`POST /notifications/{id}/read`) и задача открывается в новой вкладке.

- Версия: **1.0.0**
- Дата последнего обновления: 2026-11-17
- Англоязычный хендофф для разработчика: [HANDOFF.md](HANDOFF.md)

## Установка (режим разработчика)

1. Откройте страницу расширений: `edge://extensions` (Edge), `chrome://extensions` (Chrome), `opera://extensions` (Opera)
2. Включите **Режим разработчика**
3. Нажмите **Загрузить распакованное** и выберите папку **`extension`** внутри этой
4. (Опционально) Закрепите иконку на панели: кнопка «пазл» → значок расширения → «Показать на панели»

## Вход

Отдельной авторизации нет — расширение использует вашу сессию сайта. Просто войдите в [app.weeek.net](https://app.weeek.net) в браузере: уведомления появятся в течение полуминуты. Если вы вышли из аккаунта, бейдж исчезнет, а попап покажет экран входа: в шапке вместо «Непрочитанные уведомления» — «Checker for Weeek», ниже строка «Войдите в Weeek» и кнопка «Войти» (открывает app.weeek.net). Кнопка «Открыть Weeek» в шапке на этом экране скрыта; кнопка настроек остаётся доступной.

## Настройки

Кнопка настроек — иконка «sliders» из набора Feather — в шапке (слева от «Открыть Weeek») открывает экран настроек в том же окне: заголовок меняется на «Настройки», счётчик скрывается; повторный клик по ней или `Esc` возвращает к уведомлениям. Текст настроек и стартовых экранов (вход, ошибка, пусто) не выделяется; щелчок по любой точке строки тумблера — звука, уведомлений браузера, пути до задачи — переключает сам тумблер (курсор над такими строками указательный, при наведении строка подсвечивается). Настройки хранятся в `chrome.storage.sync` (переживают перезапуск браузера, синхронизируются между устройствами) и применяются сразу: попап будит service worker (`week:settings-changed`), фоновый скрипт пересобирает будильник опроса.

Тема оформления — второй набор пилюль в настройках, под интервалом: «Системная» (по умолчанию), «Светлая», «Тёмная». «Системная» повторяет тему Windows; явный выбор перекрывает её — тёмные токены в CSS продублированы правилом `:root[data-theme="dark"]`, светлая/тёмная ставятся атрибутом `data-theme` на `<html>` (функция `applyTheme()` в popup.js), а тёмный медиаблок ограничен гардом `:not([data-theme="light"])`, чтобы на тёмной системе явная «Светлая» не перекрашивалась обратно. Тёмные правила перекрашивают только корневые блоки переменных — элементных тёмных правил нет (закреплено тестом `test_dark_theme_overrides_variables_only`). Как и в светлой теме, фон страницы отличается от поверхностей: в тёмной он на ступень светлее (`--bg` `#1A1B1D` при поверхностях `#131416`), чтобы плитки и шапка отделялись от фона; дропдаун и подсказка ещё на ступень выше — `--surface-elevated` `#202225`.

| Настройка | Значения | Ключ |
|---|---|---|
| Интервал проверки | 30 с, 1 мин, 5, 10, 30 мин, «Отключить» | `pollIntervalSec` (0 — автопроверка выключена; список всё равно обновляется при открытии попапа) |
| Тема | «Системная» / «Светлая» / «Тёмная» | `theme` (`auto` — по теме системы; иначе атрибут `data-theme` на `<html>`) |
| Звук уведомления | вкл / выкл | `soundEnabled` |
| Уведомления браузера | вкл / выкл | `toastEnabled` (системные тосты Windows; новые уведомления запоминаются и при выключенном тосте — после включения старые не всплывают задним числом) |
| Путь до задачи | вкл / выкл | `showTaskPath` |

## Как это работает

| Параметр | Значение |
|---|---|
| Проверка новых уведомлений | по интервалу из настроек (по умолчанию 30 секунд — минимум `chrome.alarms`) + доп. проверки: при запуске браузера, при пробуждении service worker и при открытии попапа (попап шлёт `week:refresh` — фоновый опрос запускается сразу, бейдж и список обновляются на глазах) |
| Счётчик на иконке | все непрочитанные уведомления (`notifications.unread.all`), цвет `#6C78F4`, белый текст; форма скругления — на усмотрение браузера |
| Заголовок шапки | «Непрочитанные уведомления»; на экране входа и при пустом списке — «Checker for Weeek»; в настройках — «Настройки» |
| Список в попапе | непрочитанные (`GET /notifications?type=unread`), окно 456px (высота ограничена капом Chromium 600px); плитка: название задачи + строка «кто и что сделал» + текст (1–2 строки, дальше троеточие) + путь до задачи под тонким разделителем; у обрезанных строк — всплывающая подсказка с их собственным текстом: заголовок показывает только название, текст — только сообщение (общей подсказки на всю плитку нет); подсказка своя, а не системная: ширина до 320px, текст полный — без ограничения по длине и высоте, показывается только когда строка реально обрезана |
| Путь до задачи | «Проект > Доска > Колонка» (без пространства и слова «задачи»; несколько проектов — «+N»), берётся из `breadcrumbs` уведомления; включается/выключается в настройках |
| Экран входа | строка «Войдите в Weeek» (обычный текст цветом текста темы), кнопка «Войти»; кнопка «Открыть Weeek» в шапке скрыта |
| Клик по уведомлению | помечает его прочитанным и открывает `app.weeek.net/ws/{workspace}/task/{id}` в новой вкладке |
| Меню «⋯» на плитке | появляется в правом верхнем углу при наведении; точки серые (`--icon-idle`: `#CACAD2` в светлой, `#7C838B` в тёмной), при наведении на кнопку и в открытом меню — фиолетовый `#6C78F4`, без подложки кнопки; пункты «Прочитать» и «Архивировать» — без открытия задачи |
| Уведомления без задачи | открывают app.weeek.net |
| Звук нового уведомления | собственный синтезированный звук (`sounds/notification.wav`: два «блика» F5 → C6 с быстрым спадом), тихий (громкость 0.4), только при росте счётчика; первый опрос не озвучивается; отключается в настройках |
| Всплывающий тост | системный тост Windows в правом нижнем углу, длительность — стандартная Windows; клик открывает задачу и помечает уведомление прочитанным; максимум 3 тоста за одну проверку; первая проверка молчит; отключается в настройках («Уведомления браузера») |
| Полоса прокрутки | тонкая линия 3px, живёт под шапкой |
| Тема попапа | светлая/тёмная — по настройке системы или явному выбору в настройках |

## Используемые API

Публичный API (`api.weeek.net/public/v1`) не имеет эндпоинтов уведомлений, поэтому расширение использует cookie-авторизованный API:

- `GET https://api.weeek.net/user/profile/me` — счётчик (`notifications.unread.all`)
- `GET https://api.weeek.net/notifications?limit=15&type=unread` — список непрочитанных
- `POST https://api.weeek.net/notifications/{id}/read` — прочтение (клик по плитке/тосту, пункт «Прочитать»)
- `DELETE https://api.weeek.net/notifications/{id}` — архивирование (пункт «Архивировать»; восстановление — `POST /{id}/restore`)

POST-запрос требует CSRF: расширение читает cookie `XSRF-TOKEN` домена api.weeek.net (право `cookies`) и передаёт её в заголовке `X-XSRF-TOKEN`.

**Формат ответа списка**: `{success, data: [уведомления], cursor: {nextToken}}` — массив лежит прямо в `data`. Уведомление: `id`, `type`, `isRead`, `createdAt`, `workspaceId` (верхний уровень), `initiator`, `body.nodes` (узлы `initiator`/`text`/`entity`/`content`/`new_line`/`task_locations`/`datetime`; задача — узел `entity` c `entity.type === 'task'`, поля `entity.id` и `entity.title`; `content` — rich-text документ, реакции — тип `task.comment.reacted`) и **`breadcrumbs`** (верхний уровень; путь до задачи: `entity`-узлы и узел `task_locations` с цепочкой `project → board → boardColumn`). Все ответы обёрнуты в конверт `{success, data}`.

Запросы выполняются с вашими сессионными cookies только на `api.weeek.net` и `app.weeek.net`; никакие данные никуда не отправляются.

## Иконки

Шапка текстовая (заголовок «Непрочитанные уведомления»), строка «Войдите в Weeek» на экране входа — обычный текст, а все иконки интерфейса (плитки, меню «⋯», кнопка настроек — «sliders») — на базе набора [Feather Icons](https://feathericons.com) (MIT). Edge не принимает SVG для иконок панели (`manifest.icons`), поэтому 16/32/48/128 — PNG иконки приложения — собственный знак «W» (#016BFF, вектор [`assets/logo-w.svg`](../assets/logo-w.svg) хранится в репозитории).

## Отладка

- Логи фонового опроса: страница расширений (`edge://extensions` / `chrome://extensions`) → «Checker for Weeek» → **Служебная программа** → **Inspect**
- В `extension/background.js` флаг `DEBUG = false` — при включении (`true`) сырой JSON одного уведомления пишется в консоль service worker (`[weeek-ext] raw notification sample`); полезен для сверки маппинга полей при изменениях API.
- Ход тостов виден в консоли service worker при включённом DEBUG: `[weeek-ext] toast flow: fresh = N` и `[weeek-ext] toast created: …`
- Попап без установки: откройте `extension/popup/popup.html` в браузере — отрисуется с демо-данными; тёмная тема — в devtools поставьте `<html data-theme="dark">` (или выберите «Тёмная» в настройках попапа)

## Если API изменится

Внутренний API не документирован и может измениться. Все запросы собраны в `extension/background.js` (`fetchJSON`, `extractUnread`, `normalizeNotification`) — править нужно только там.
