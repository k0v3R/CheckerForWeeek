# Тесты расширения

Два слоя тестов: статические проверки на Python (stdlib, без зависимостей) и
юнит-тесты настоящего JS-кода в браузерном движке (HTML-раннеры).

## Python (структура, ассеты, доки, строки)

```bash
python -I -m unittest discover -s tests -v
```

| Файл | Что проверяет |
|---|---|
| `test_manifest.py` | manifest.json: MV3, поля, версия 1.0.0, permissions, все указанные файлы существуют |
| `test_css.py` | Конфликты `hidden` с авторскими display-правилами CSS попапа (`.list[hidden]` и парные правила для остальных классов) |
| `test_references.py` | Все пути из JS/HTML существуют; PNG-иконки точных размеров 16/32/48/128; notification.wav — RIFF/WAVE |
| `test_docs.py` | Версия и имя согласованы в README/docs; permissions в доках == manifest; главный инвариант GET-only задокументирован |
| `test_strings.py` | Экстракция всех UI-строк + механика (баланс «», пробелы, регистр бренда Weeek — строчное weeek вне доменов запрещено); список строк → `strings_report.txt` |

## Браузерные раннеры (настоящий код в настоящем JS-движке)

Страницы подключают продакшн-скрипты тегом `<script>` после стабов
(`chrome`/`fetch`/DOM), поэтому тестируется реальный код, а не копия.
Работают и с `file://`, и через локальный сервер:

```bash
python -m http.server 8741   # из корня репозитория
# затем открыть:
#   http://127.0.0.1:8741/tests/runner-background.html  — парсинг уведомлений (normalizeNotification и др.)
#   http://127.0.0.1:8741/tests/runner-popup.html       — логика попапа + демо-рендер
#   http://127.0.0.1:8741/tests/runner-offscreen.html   — воспроизведение звука
```

Итог каждого раннера — в заголовке вкладки (`PASS: N / FAIL: M`) и в списке
на странице.

## GUI smoke-тест попапа (демо-режим)

```bash
python -m http.server 8741
# открыть http://127.0.0.1:8741/extension/popup/popup.html
```

Проверить руками/автоматизацией: плитки, тултипы обрезанных строк, меню «⋯»
(«Прочитать» удаляет плитку в демо), настройки (иконка настроек/Esc/тумблеры),
тёмная тема — `<html data-theme="dark">` в devtools.
